# 抖音图文稿丰富化设计

## 目标

把现有 8 张轮播提纲改成面向非技术观众的可发布素材：先让读者理解“机器人找红色目标”这件事，再用少量可核验数据建立可信度，最后透明说明非官方边界、模型闭环已完成但 0.5m 目标成功率为 0/10，以及下一步。

## 叙事结构

1. 问题钩子：一个英文指令如何变成机器人动作。
2. 边界声明：个人非官方实验，不是课程原样复现，也不提交榜单。
3. 场景拆解：G2、头部相机、RGB/depth、loopback HTTP 和四个动作。
4. 数据证据：3 条冒烟、50 条训练、10 条固定种子评测，以及 sidecar 保存内容。
5. 训练证据：LoRA 训练通过、独立进程重载通过，但 `train_loss=0.0` 只作观测，不作质量结论。
6. 结果分层：base 和 LoRA 真实闭环均为 0/10@0.5m；控制器冒烟成绩单独列示，不能混写。
7. 失败复盘：USD AABB 稳定性问题和 GenieSim sidecar 与公开 Habitat evaluator 的边界。
8. 收束互动：下一步需要兼容资产和 sidecar evaluator，邀请读者关注真实复盘而非包装案例。

## 每张图的交付字段

- 标题：不超过两行，避免堆砌缩写。
- 画面：对应现有截图、GIF 或视频，不能使用未生成的占位素材。
- 屏幕字幕：一句白话 + 一条关键证据。
- 正文：2–4 句，可直接复制到抖音图文说明或作为轮播旁白。
- 评论引导：一个具体问题，鼓励读者讨论“真实闭环”和“模型成绩”的区别。

## 真实性与合规

- 公开署名只用“智元布道师个人实验”。
- 不出现账号、邮箱、IP、实例 ID、连接信息、私有权重或 adapter 文件。
- 不把控制器成绩改写成 StreamVLN 模型成绩；base/LoRA 配对导航结果从 `eval_result.json` 读取，公开标注为 0/10@0.5m 的失败复盘。
- 发布流程保留为：素材完成 → 用户登录 → 草稿预览 → 用户确认最终提交 → 审核中。
