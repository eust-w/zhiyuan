# 05｜结果分析：哪里真的好了，哪里仍然没学会

## 先把事实分层

| 层次 | 已验证事实 | 不能越界的结论 |
| --- | --- | --- |
| 仿真 | G2、RGB/depth、pose、两帧等待、loopback API 真实运行 | 不是课程私有 UDP 原样实现 |
| 安全 | head-depth 近障碍拒绝且位姿不变 | 不是完整 USD AABB planner |
| 数据 | 3 + 50 + 10，train 50/50、eval 10/10 严格通过 | 控制器成功不能代替模型成绩 |
| 资产 | 自采 PLY/USDA/USDZ 同源并在新 Isaac 进程打开 | 不是课程 sample 原件 |
| 训练 | 59 个非零更新步，loss 0.4167→0.0823，新进程重载通过 | loss 下降不等于导航成功 |
| 模型 | base/LoRA 同一 10 条真实闭环 | 0.5m 成功均为 0/10，不能包装成成功案例 |

## 排障一：为什么第一次训练是“假成功”

上游命令使用 `--version qwen`，但公开 `conv_templates` 没有这个键，脚本静默回退到 Vicuna v1；动作标签全部被 mask，结果是退出码 0、loss 0、grad_norm 0。修复不是“接受这个结果”，而是：

1. 使用真实存在的 `qwen_2` 模板；
2. 按 token 字符串取得 Qwen 起止 special ID；
3. 将非零 loss 与非零 grad_norm 设成硬门；
4. 保留失败 gate，不把旧 adapter 当训练产物。

第二个问题是 checkpoint 的旧 `config.vocab_size=152064` 与实际 `lm_head.out_features=151648` 不一致，首 batch reshape 会失败。兼容层在 vision tokenizer 初始化后以实际 `lm_head` 行数对齐配置，单 batch 和完整训练才真正通过。

## 排障二：为什么历史 episode 不把独立 AABB 探针写成 HTTP 闭环

当前 G2/市场视觉资产包含 malformed face-varying primvar，运行时完整 `BBoxCache` 遍历会令 SimulationApp clean shutdown，Python 层拿不到可恢复异常。新增的等价 `market-aabb-proxy.usda` 已通过独立 Isaac/PXR 探针完成 authored Cube AABB 投影和 footprint+5cm 膨胀；但同一视觉 HTTP 进程仍未进入 `occupancy_built`，所以不把探针结果伪装成历史 episode 的相机闭环。历史 episode 继续使用可审计的 head-depth 安全门：中央视野第 10 百分位深度低于 0.45m 时拒绝前进，`blocked_source=head_depth_forward_guard`。

因此 Stage 3 的 132/45 次碰撞不是机器人穿模后的“物理撞击”，而是 base/LoRA 尝试危险前进、被传感器安全门拦截的次数。这比报告 0 碰撞更真实，但仍不等价于课程 AABB + footprint planner。

## 排障三：LoRA 为什么训练正常却更差

最终结果：

- base：0/10@0.5m，2/10@3m，平均最终距离 3.989m；
- LoRA：0/10@0.5m，1/10@3m，平均最终距离 4.686m。

LoRA 平均只走 53.2 步，base 为 133.9 步；LoRA 碰撞尝试也更少，但平均最小距离从 base 的 2.884m 退化到 3.482m。动作策略更短、更谨慎，却没有更接近目标，说明小数据 LoRA 更可能学到“早停/少探索”，没有学到稳定的目标识别与停止条件。

训练末端不少图像里红色目标并不清晰，这进一步说明目标可见性、终点视角和指令-图像一致性比单纯再加 epoch 更值得先修。

## 下一轮只改三件事

1. 替换能稳定离线导出 AABB 的兼容 USD，恢复 5cm 栅格、footprint + 5cm inflation。
2. 放大并调整红色目标牌位置，筛掉终点看不到目标的轨迹，再补目标相关语言改写。
3. 保持 `eval-2001…2010` 不变，先做数据修复，再复用同一 base/LoRA 协议回归。

在 `success@0.5m` 出现可复现成功 episode 前，对外内容保持“非官方等价适配失败复盘”。
