### 03｜机器人不是凭空行动：先把感知和动作拆开

**画面：** `../assets/screenshots/P1-smoke-0016.jpg`

**画面上文字：**

> G2 Omnipicker + 头部相机
>
> RGB / depth / pose → HTTP → 动作

**正文：**

在 `market_00_g2` 场景里，我给 G2 接上头部相机，同时保存三类信息：

- RGB：机器人看到的彩色画面；
- depth：每个像素离相机有多远；
- pose：机器人此刻在场景里的位置和朝向。

动作空间也被固定成四个数字：`0=STOP`、`1=前进 0.25m`、`2=左转 15°`、`3=右转 15°`。

HTTP 服务只监听本机 loopback。换句话说，线程负责收请求，真正的仿真动作仍回到 Isaac 主线程执行，避免网络线程直接碰仿真状态。

**评论引导：**

你觉得具身智能里最难对齐的是“看见”、 “理解”，还是“动起来”？

### 04｜先采数据，再谈训练：3 + 50 + 10

**画面：** `../assets/gifs/stage1-smoke-controller.gif`

**画面上文字：**

> 3 条冒烟轨迹
> 50 条训练轨迹
> 10 条固定种子评测轨迹

**正文：**

我没有直接按下训练按钮，而是先做了三层数据准备：

第一层是 3 条冒烟轨迹，确认 RGB、depth、位姿和动作数组能保存；第二层是固定种子 `1001–1050` 的 50 条训练轨迹；第三层是完全留出的 `2001–2010` 评测轨迹。

公开的 `annotations.json` 遵循 StreamVLN 数据格式：首动作是 `-1`，RGB 数量和动作数组一致，最终 STOP 不塞进公开数组。完整 STOP、depth、轨迹、目标距离和碰撞结果，另外放进 `geniesim-streamvln/v1` sidecar。

这样做的意义是：别人看得到“模型输入是什么”，也看得到“仿真实际发生了什么”。

**评论引导：**

你做实验时，会把训练数据和评测数据固定分开吗？

### 05｜动作之后，至少等两个渲染帧

**画面：** `../assets/screenshots/P1-smoke-0026.jpg` + GIF 局部动图

**画面上文字：**

> 每次移动后等待两个渲染帧
>
> 再保存 RGB / depth / pose / collision

**正文：**

这一步看起来很细，但它决定了数据是不是可信。

如果动作刚发出去就立刻抓图，RGB 可能还是上一帧，depth 可能还没有更新，位姿和碰撞状态也可能对不上。于是我把流程固定成：提交动作 → 等至少两个渲染帧 → 写入四类观测 → 再进入下一步。

最后每条 sidecar 都能回答四个问题：机器人在哪儿？看到了什么？有没有被挡住？离目标还有多远？

**评论引导：**

你遇到过“日志显示成功，但画面其实是上一帧”的问题吗？

### 06｜训练通过，不等于模型已经会导航

**画面：** `../assets/carousel/carousel-06.jpg`

**画面上文字：**

> LoRA 50 步训练：通过
> 新进程 adapter 重载：通过
> 但 train_loss = 0.0：不做质量结论

**正文：**

Stage 2 最后确实跑通了：LoRA 配置是 `r=8`、`alpha=16`、dropout `0.05`，1 个 epoch、batch 1、BF16；50 个训练样本完成，adapter 也在一个全新的 Python 进程里重新挂载成功。

但日志里的 `train_loss=0.0` 我只当作观察值，不当作“模型学得很好”的证据。训练能保存权重，和模型能在新场景里做出正确动作，是两件不同的事。

这也是为什么我把“训练通过”和“模型导航成绩”分开写。

**评论引导：**

你会把“权重保存成功”当成“模型效果成功”吗？

### 07｜同一批 10 条，base 和 LoRA 都没有过线

**画面：** `../assets/carousel/carousel-07.jpg` 或 `../assets/gifs/stage1-smoke-controller.gif`

**画面上文字：**

> base：0/10 · LoRA：0/10（目标半径 0.5m）
>
> 这是模型真实闭环，不是控制器代跑

**正文：**

这一次，模型不是旁观者：base 和 LoRA 都读取同一批 RGB/depth/指令，生成自己的动作序列，再由 GenieSim 执行到底。

结果非常诚实：base 的 `success@0.5m=0/10`，平均最终距离 `3.866m`、SPL@3m `0.093`、碰撞 5 次；LoRA 也是 `0/10`，平均最终距离 `4.302m`、SPL@3m `0.083`、碰撞 0 次。LoRA 少撞了，但没有把机器人带到目标半径内。

这能证明的是：模型→HTTP→仿真→指标这一条链路真实存在；不能证明这套非官方适配已经达到可用导航质量。

**评论引导：**

看到“0/10”时，你会先问一句：失败发生在模型、输入，还是资产？

### 08｜失败也要有下一步，而不是一句“以后再说”

**画面：** `../assets/carousel/carousel-08.jpg` + 竖屏视频最后一帧

**画面上文字：**

> 下一步：兼容 USD 资产
> + 更有效的目标相关训练数据

**正文：**

这次有两个明确缺口。

第一，当前 G2 USD mesh 在做 `UsdGeom.BBoxCache` AABB 投影时会触发 SimulationApp clean shutdown，所以本轮仍使用运行时安全 fallback 栅格，不把它宣传成课程私有 USD 原样障碍评测。

第二，depth annotator 的全非有限帧采用了可审计的 sensor max-range fallback；它保证接口继续可消费，但不等于真实深度精度证明。

第三，模型评测器已经补齐，缺口从“没有闭环”变成“闭环已完成但效果为 0/10”。下一步是换兼容 USD 资产、改善深度和目标相关训练数据，再复用同一批 10 条 episode 回归。

**评论引导：**

如果你愿意继续看这条线，下一期你想先看障碍栅格，还是先看模型 evaluator？

## 可直接发布的长正文

你会把“10/10 成功”直接写成模型成绩吗？

这次实验里，我刻意没有这么写。

我给 G2 一个简单指令：**Walk toward the red beacon and stop.** 然后在 `market_00_g2` 场景里记录 RGB、depth、pose、动作、碰撞和目标距离，先跑通仿真和数据闭环，再做 LoRA 训练。

最终有四件事同时成立：

1. 3 条冒烟、50 条训练、10 条固定种子评测轨迹通过数据校验；
2. LoRA 50 步训练完成，adapter 能在新进程中重新挂载；
3. base 与 LoRA 都在同一批 10 条 held-out episode 上真正生成动作并进入 GenieSim；
4. 唯一指标源完整记录 success、SPL、距离、步数、碰撞和动作计数，但 0.5m 成功率均为 0/10。

但还有一件事没有成立：**模型还没有在这个等价兼容场景里完成目标导航。** 这比“评测没跑”更具体，也更值得公开：失败发生在真实闭环里，下一轮可以针对输入、资产和训练数据逐项修复。

所以这不是官方适配，也不是成功案例包装，而是一份把“跑通了什么、没跑通什么、下一步怎么补”都写清楚的个人实验。

你更想看下一期的哪一部分：

- USD 障碍栅格为什么会让仿真退出？
- sidecar evaluator 怎么把模型真正接回闭环？
- 还是 base / LoRA 的同集对比？
