## 2. 已落地的修复

### 独立的 CPU/媒体锁与审计锁

直接导入对应 NumPy、Pillow、OpenCV headless、PyYAML、edge-tts。新环境不再依赖任意全局安装状态；包含传递依赖、venv 安装器 pip 和每个版本的分发哈希。当前直接版本为 NumPy 2.5.4、Pillow 13.0.0、OpenCV headless 5.0.0.93、PyYAML 6.0.3、edge-tts 7.3.1；pip 固定为 26.2.2，避免文档/CI 创建 venv 后遗留未纳入扫描的旧安装器。Pillow 的旧上游 11.2.1 不再作为本项目媒体环境安装选择。

原媒体包的实际安装版本没有完整记录，因此不声称“某台旧机器已从版本 X 升级到 Y”。这次修复的是仓库可重复安装的推荐 CPU profile；没有原地修改用户机器或云端环境。

新增 [CI 工作流](../.github/workflows/dependency-audit.yml)：哈希固定的 Actions、只读仓库权限、分离的审计器 venv、两份锁都扫描、安装后检查依赖、运行相关单测。未添加漏洞忽略项。

### 模型文件加载加固

[model_security.py](../aima-open-session-experiment/adapter/model_security.py) 现在在导入外部模型代码之前检查：

- 模型和视觉塔必须是本地目录；配置必须为 JSON 对象。
- safetensors 单文件或索引中的每个分片必须存在、非空，解析后的路径不能逃出模型目录；拒绝绝对路径、`..` 和越界 symlink。
- 拒绝模型目录内 `.bin/.pt/.pth/.pkl/.pickle` 权重；LoRA 必须提供 `adapter_model.safetensors`，拒绝 `adapter_model.bin`。不读取的 `training_args.bin` 元数据可保留在 adapter 输出目录。
- 自有 Transformers 加载点指定 `use_safetensors=True`、`local_files_only=True`、`trust_remote_code=False`；PEFT 使用其本地 safetensors 选择机制及前置检查，不传不存在的格式开关。
- 设置 Hugging Face 离线变量，训练前检查完整分片；显式 `np.load(..., allow_pickle=False)`；检查 Qwen/SigLIP 兼容 symlink 的实际目标。
- 拒绝基座/视觉模型目录的 `adapter_config.json`，避免 Transformers 自动将实际加载路径重定向到未检查的基座；PEFT adapter 使用独立入口。
- Stage 2 把基座配置中的视觉塔引用与 `--vision` 绑定到同一真实目录。缺失、远端/相对路径、冲突引用都会阻止执行，且不修改原始模型配置；这可能拒绝旧的不可移植配置，需要在独立兼容副本中核验后再运行。

这是输入边界加固，**不是历史 Transformers/Torch 的版本修复**。它不验证模型内容安全，不防止目录在检查后被并发修改，不沙箱化直接导入的 StreamVLN，也不能代替外部训练/视觉加载代码审查。

## 3. 仍然开放的问题

旧上游有命中的包包括 Accelerate、aiohttp、anyio、certifi、datasets、DeepSpeed、filelock、fontTools、fsspec、GitPython、h11、hydra-core、idna、marshmallow、msgpack、Pillow、protobuf、pyarrow、pydantic、Pygments、python-dotenv、requests、scikit-learn、sentencepiece、Starlette、Torch、Transformers、urllib3。全部明细、公告别名和修复版本保存在原始 JSON；这里不通过删除包或忽略公告把旧栈“变绿”。

例如 Transformers 4.45.1 涉及的 [GHSA-xrqw-3rrv-vx5w](https://github.com/advisories/GHSA-xrqw-3rrv-vx5w) 修复版本已到 5.10.0。只升级到早期计划的 4.51.0 不足以处理本次发现的所有公告。[Transformers v5 迁移指南](https://github.com/huggingface/transformers/blob/main/MIGRATION_GUIDE_V5.md) 记录了 tokenizer、权重加载和 Hub API 变化，不能把改 pin 当成 StreamVLN 已兼容。

人工补充：[PyTorch GHSA-63cw-57p8-fm3p](https://github.com/advisories/GHSA-63cw-57p8-fm3p) 的公告包名为 `pytorch`，与通常安装的 `torch` 不同；仅按 PyPI 包名查询存在漏报风险。该条未加进上述 pip-audit 原始统计，也不被 safetensors 前检等同于全部修复。某些公告没有提供修复版本或不同来源存在冲突，必须逐项核实，不能统一声称已清零。

### 模型栈的下一道验收门

1. 在新的、与 Isaac 分离的受支持 Python 环境中解析安全模型依赖；先审计完整传递依赖，核验上游源码与权重许可。
2. 迁移 StreamVLN 自定义模型、慢 tokenizer、模板和 PEFT 接口；先做离线小模型/小数据加载测试。
3. 在获授权的 GPU 预算内执行真实 checkpoint 加载、dataset-only、单 batch 前后向、adapter 保存与新进程重载、base/LoRA 闭环冒烟测试。
4. 对实际环境导出完整安装清单，重新审计；若需与历史结果比较，使用同批 held-out 重评并单独记录，不覆盖旧指标。

本次没有完成以上 GPU 迁移，因此旧环境保留“未修复/不推荐新安装”状态。
